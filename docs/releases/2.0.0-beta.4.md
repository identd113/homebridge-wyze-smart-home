# Release notes: homebridge-wyze-smart-home 2.0.0-beta.4

The changelog is written for people installing the plugin. This page is for whoever ships and supports it: what changed in the code, the exact settings and defaults, what has been checked on real hardware and what has not, and what is known to be unfinished.

**Compared against:** `v2.0.0-beta.3` (`4031e56`, published 2026-10-26), the last published release. `beta.4` is 72 commits and 64 files (+5,781 / -241 lines) on top of it, not counting the release commit itself. Always compare against the last *published* release, not against the working branch.

**Pairs with:** `wyze-api@2.0.0-beta.4` (see that repository's `docs/releases/2.0.0-beta.4.md`). `dependencies.wyze-api` is `^2.0.0-beta.4` on purpose: the features below need it, and with beta.3 they switch themselves off.

## Upgrading

1. **Breaking: the Privacy switch is now on when the camera is off.** It used to be on when the camera was on, the opposite of its name. There is no setting to keep the old direction. Any scene, automation or Siri phrase that uses a camera's Privacy switch now does the opposite and must be changed. Say so first in the release text.
2. **New HomeKit tiles appear by themselves.** Each camera whose last week of events shows motion gets a Motion Sensor, one that shows sound gets a Sound Sensor, and one whose events carry Wyze's AI labels gets Person, Vehicle, Pet and Package sensors. They can be turned off per camera on the plugin's settings page. HomeKit may start notifying for them.
3. **Needs `wyze-api` 2.0.0-beta.4.** The range makes npm install it. With an older copy the bulk property read is skipped (one warning) and the Cam Plus plan lines are left out.
4. **Rollback:** `npm install homebridge-wyze-smart-home@2.0.0-beta.3`. The config keeps working; the new per-camera settings are ignored by beta.3. Cameras then have the old Privacy direction again.

## New settings

Per camera (in the `cameras` list, or on the settings page), and one under `advanced`:

| Setting | Default | What it does |
|---|---|---|
| `cameras[].motionSensor` | `auto` | `auto` adds a Motion Sensor when the camera's events show motion; `on` always adds it; `off` never. |
| `cameras[].soundSensor` | `auto` | The same for the Sound Sensor. |
| `cameras[].detections` | empty = automatic | A list such as `["person", "pet"]` for exactly those AI sensors; `["none"]` for none. Face is added only by name. Names the plugin does not know are kept and ignored. |
| `advanced.sensorHoldSeconds` | empty = 120 (5 to 3600) | How long a sensor stays on after the event, counted from the event's own time on Wyze's clock. |

## What changed in the code

### Cameras (`src/accessories/WyzeCamera.js`, `src/camera/*`)

- Motion, Sound and AI-label sensors (`detectionSensors.js`, `sensorHold.js`): a sensor reacts to a new event id whose age is 30 seconds or less, stays on for the hold time and is extended by a newer event. Discovery reads the last week of events, repeats (every 30 minutes while a Motion or Sound sensor is missing, every 6 hours otherwise) and says what it found only when that changes. Motion and Sound ask Wyze for their own event types, so a week of one cannot crowd the other out of the 20 events a request returns.
- One poll for every camera (`motionPoller.js`): the cameras share a request. Wyze returns at most 20 events in all, so when an answer is full the cameras that came back empty are asked for again (up to three rounds), and one busy camera cannot hide another's motion.
- Properties for cameras and lights are read in one request per refresh (`propertyPoller.js`), with the per-device read as the fallback.
- Privacy switch: on means the camera is off. A camera that is switched off shows a black picture with a crossed-out red dot in the Home app instead of its last picture, and the plugin updates its idea of the camera's power as soon as Wyze accepts the switch. `power_switch` also follows the property list, so this works for cameras with an attached accessory.
- Cam Plus plans (`plan.js`): looked up once per start (retried after 10 minutes if it failed), noted for the settings page, and logged: a camera with no plan, a lapsed plan, or one ending within 14 days.

### Settings page (`homebridge-ui/`, `src/detectedSensors.js`)

- A "Detected sensors" panel: each camera's sensors as on/off pills with an AI mark on AI labels, its Cam Plus plan, and a line above the cards for each live plan. The Sound pill is greyed out with a warning when the camera's sound recording is off in Wyze. The plugin writes what it finds to `detected-sensors.json` under Homebridge's storage folder; the page only reads it.
- Save changes only what the user changed: `detections` is left alone unless a detection pill was changed, nothing but that camera's keys may differ, and Save stops with a message when the settings form has edits that are not saved yet. Every change is checked first and nothing is saved when a check fails or cannot finish.

### Packaging and project

- `package.json` has a `files` list: with only an `.npmignore`, npm ignores `.gitignore`, so local files such as a Homebridge `config.json` or `persist/` folder would have been packed.
- `CLAUDE.md` and `AGENTS.md` are untracked and ignored. A test fails if one is tracked again or if the package would hold a private file.
- `docs/releasing.md` and a docs index `docs/README.md` are new.

## What has been checked, and how

### Checked on the test bridge (real cameras: a Cam v2, two Cam v3 and a doorbell)

- The bulk property poller and the Motion, Sound and AI-label discovery run against the real cameras; the note file records each camera's sensors, sound-recording state and Cam Plus plan, and the plan lines appear in the log (the one covered camera, and the others as "no plan").
- Privacy: setting it powers the camera off or on at Wyze (Wyze reports the power change within seconds and live view is refused while it is off), and the owner confirmed the inverted direction in the Home app.
- Wyze lists events late: a sound at the Garage was seen by the plugin about 8 seconds after Wyze listed it.

### Unit tests only

- The settings panel logic (run in a `vm`): saving, the new Save rules, the Sound-recording warning, the plan lines. The sensor hold timing (with mocked timers), repeated discovery, the fair-share polling, the plan retry, the power-state fix, the camera-off picture, the package contents and the private-file guards.

### Not verified on hardware

- The final settings page (the Sound-recording warning, the plan lines and the new Save rules) in a real Homebridge UI.
- The camera-off picture in the Home app after the last fix.
- The build with the code-review fixes from 2026-11-01 has not been run on the test bridge. Update this line after it has.
- Sensors firing from real motion after discovery was changed to repeat, and Face and other rare AI labels with real data.
- How a camera on a Wyze plan chains events during long motion; the 120 second hold is built for it.

## Known issues and deferred work

- A camera without a Wyze plan gets an event about every 5 minutes, so its Motion and Sound sensors can lag or skip. That is Wyze's cooldown.
- One device missing from the bulk property read makes the whole read fail for that cycle; every device then falls back to its own request, so the saving is lost while that device is in the group.
- HomeKit's own camera on/off control is built but held back for beta.5 (branch `feature/native-camera-power`). HomeKit Secure Video is not planned: it needs a permanently open camera connection and a Wyze camera serves one viewer at a time.
