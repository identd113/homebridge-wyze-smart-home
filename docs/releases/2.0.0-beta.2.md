# Release notes: homebridge-wyze-smart-home 2.0.0-beta.2

Published to npm on 2026-08-29 under the `beta` tag. The tag is `v2.0.0-beta.2`, 17 commits after `v2.0.0-beta.1`.

**Pairs with:** `wyze-api@2.0.0-beta.2`.

This release merges the unreleased 0.5.x hardening work from `main` (24 commits since the branches last synced) into the 2.0.0 line. The two lines had built overlapping features separately (two Lock Bolt V2 / Palm Lock implementations, two thermostat fan, emergency heat, hold and keypad-lock implementations), so 18 conflicting files were combined by hand.

## What changed

- **Optimistic setters with command grace periods** for plugs, lights, mesh lights, switches, HMS, locks and Lock Bolt V2. A Set updates HomeKit at once and calls the API in the background; a poll that lands before Wyze has applied the change does not revert it (15 s for lock, 90 s for unlock). Before this only locks had it on the 2.0.0 line.
- `WyzeLockBoltV2` gained charging state, firmware version and fast `iot-device::iot-state` offline detection.
- `WyzeThermostat` gained fan mode, emergency heat, hold, keypad lock and scenario switches, using `wyze-api`'s conversion helpers.
- A `ModelNames` lookup and consistent log prefixes on every accessory.
- Less log noise, plus null-guard fixes from `main`'s review passes.

## Breaking changes

None.

## Known gaps at release

- Same dependency audit findings and missing Node `engines` tightening as beta.1 (fixed in beta.3 and beta.4).
